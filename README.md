## 🛠 실무 프로젝트 하이라이트 (일반화 서술)

**1. 멀티채널 재고 배분·동기화 파이프라인** — Node.js
- 문제: 여러 채널이 같은 창고 재고를 나눠 쓰면서 수작업 배분 → 오버셀·품절 사고 위험.
- 설계: 채널별 배분율 정책 + 저재고 컷오프, 자사몰 API 자동 푸시 + 마켓플레이스 업로드 시트 생성,
  평일 정시 자동 실행(launchd) + 메신저 웹훅 알림, 실행 이력 append-only 저장.
- 결과: 국가별 재고 배분을 **평일 매일 무인 실행되는 루틴으로 전환해 수개월째 운영 중**,
  동일 구조를 두 번째 국가 채널로 이식하고 타 담당자에게 인수인계까지 완료.

**2. 마켓플레이스 모니터링·재고 자동화** — Python
- 시간별 매출 추적, 재고 임계치 알림(cron으로 매시간 상시 구동 중), API 기반 재고 자동 입력
  스크립트 일체를 구축해 일상 운영에 사용.
- 인증서 기반 API 클라이언트, "응답 Success ≠ 실제 반영"을 전제로 한 사후 검증 로직 포함.

**3. 사내 커머스 플랫폼 — 프로모션 기획 모듈 기획·설계**
- 행사 기획 업무를 화면으로 옮기는 모듈에서 **요구정의, 화면·데이터 구조 설계, 릴리스별 검수를
  직접 수행** (구현은 사내 개발 리소스와 협업). 매출 자동 집계, 할인·마진 시뮬레이션, 다국가 지원,
  산출물(기획안·디자인 요청서) 자동 생성까지 반복 릴리스로 확장.

**4. 마켓플레이스 ↔ 풀필먼트(3PL) 연동**
- 주문·출고 API 연동을 등록·검증하고, 리스크를 줄이기 위해 수동 운영과 병행하는 단계적
  컷오버로 설계. 키 만료 주기를 캘린더로 관리해 무중단 갱신.

**5. 운영 안전 체계 (모든 자동화의 공통 원칙)**
- 라이브 변경 전 타임스탬프 백업 → 변경 → 검증 → 종료 시 원복. dry-run이 기본값, 라이브는 명시적.
- 장애·실수 사례를 회고 문서로 축적해 다음 자동화의 가드레일로 재사용.
